agentproto 2026-09-30 lands AIP-16 IO schema well-formedness checks on tool manifests.

GitHub (agentproto/ts) · 2026-09-30 · Source ↗

The TypeScript reference implementation of agentproto cut its 2026-09-30 release Wednesday with AIP-16, which adds IO schema well-formedness checks to tool manifests at parse time. The runtime continues to project tools, skills, agents and workflows into CLI, HTTP, MCP, SDK, Mastra and the AI SDK surfaces simultaneously, with any-coding-agent background execution and check-before-landing semantics.

agentproto, the open-source agentic runtime whose TypeScript implementation ships as @agentproto/ts, cut its scheduled release Wednesday under the 2026-09-30 tag. The headline change is AIP-16, the agentproto improvement proposal that formalizes IO schema well-formedness checks on tool manifests. Prior releases accepted tool manifests whose input and output schemas were syntactically valid JSON Schema but semantically malformed (recursive without base case, required properties absent from the properties map, enum entries whose constants did not match the declared type). AIP-16 moves those checks into the manifest parser so the runtime rejects malformed manifests at load time rather than at first tool call.

agentproto's design has been that any coding agent (Claude Code, Codex CLI, Devin, Aider, and the full long tail) can be run as a background process managed by the runtime, with the runtime providing a uniform tool, skill, agent and workflow surface across CLI, HTTP, MCP, SDK, Mastra and the AI SDK. The 2026-09-30 release continues that pattern and adds the first-class manifest validation layer that teams running mixed internal and vendor-supplied tools have asked for.

"Projects every tool, skill, agent and workflow into every surface, and rejects malformed manifests at parse time." — agentproto release notes

Why the schema check matters

Tool manifests supplied by vendors have become a quiet source of agent flakiness. An agent that calls a tool with semantically malformed schema fails at runtime, often with error messages that get swallowed inside orchestration layers and surface to the user as "the agent gave up." Moving the check to parse time means a bad manifest never enters the registry. The release notes flag the migration path: existing manifests that pass JSON Schema syntax but fail the new well-formedness pass will emit a warning on load, with a hard-fail flag landing in the next release. Teams managing large internal tool catalogs are the primary beneficiaries.

vLLM proposes programmable KV cache policies for agentic workloads in RFC #57103.

agents-radar digest · 2026-09-30 · Source ↗

vLLM opened RFC #57103 Wednesday for programmable KV cache policies, letting agent frameworks specify retention and eviction behavior on a per-session basis rather than relying on the current block-aware LRU. The RFC targets long-running agent loops that replay a stable system prompt across hundreds of turns with branching tool-call episodes.

vLLM's maintainers filed RFC #57103 Wednesday as a proposal to let frameworks register custom KV cache policies against individual engine instances. The default policy in vLLM has been block-aware LRU with prefix caching, which is correct for chat workloads where the useful prefix is roughly the latest system plus user messages. Agentic workloads look different: a long-lived agent loop replays a stable system prompt plus a growing tool-call ledger across hundreds of turns, and the branching structure of tool calls creates sibling episodes that an LRU policy evicts aggressively.

Under the RFC, a framework can supply a policy object that implements retain/evict/score hooks against the current cache state and the incoming request. The policy sees the full block table and can pin high-value prefixes, bias toward retaining branch points for parallel subagents, or implement explicit tree-structured retention for lead-agent-plus-worker patterns. The RFC specifies both a Python API for prototyping and a C++ ABI for in-engine policies that cannot afford GIL round-trips. Discussion so far has centered on sandboxing: a buggy policy that pins everything degrades to an engine OOM, so the RFC proposes a watchdog that reverts to the default policy on invariant violation.

"Programmable KV cache policies for agentic workflow memory management." — RFC #57103 title

Related stability work

The same Wednesday digest flagged two critical open stability issues: GLM-5.3-Flash hitting illegal memory access on the current vLLM main, and DeepSeek-V4.1-Flash CUDA crashes under high concurrency. PR #51406 landed ROCm optimization for Qwen3.8-2.4T-A95B on MI355X with fused kernels, delivering throughput wins for the largest open MoE in production inference workloads. The RFC and the stability work both aim at the same long-tail: agentic workloads at scale with heterogeneous model and hardware mixes.

CoEM, posted to arXiv on Wednesday under the title "Empowering Long-Context Reasoning with Commit-on-Evidence Memory," argues that one of the dominant failure modes of long-context reasoning is unverified-fact propagation. A model surfaces a plausible-looking assertion mid-way through a chain, folds it into its working context, and reasons downstream against it as if it were ground truth. The paper's framing is that the mechanism separates "candidate" and "committed" memory. Downstream reasoning operates against committed memory, with candidates visible only in a scratchpad channel. The authors argue this is closer to how human experts work complex cases: a hypothesis is held provisionally and only promoted to a working belief after supporting evidence surfaces.

"The compound-interest problem of long-context reasoning is unverified assertions earning fictitious interest." — CoEM paper abstract

The paper reports measurable reductions in long-horizon hallucination on legal case analysis and scientific literature review, two domains where unverified intermediate assertions compound into incorrect conclusions.
