NaiveAI ships a 309B open-weight MoE with no full attention anywhere in the stack.

The Beijing startup led by former Microsoft Research Asia and SenseTime scientist Jifeng Dai published Naive-N0.5-Flash on Hugging Face under an MIT license Sunday, a 309-billion-parameter mixture-of-experts model with 15.5 billion active parameters, native one-million-token context, and forty-eight transformer layers that skip full attention entirely. Thirty-nine of those layers use a 128-token sliding window; the remaining nine use DeepSeek Sparse Attention with a top-2,048 selection. NaiveAI says the model was trained on 3.25 trillion tokens starting from Xiaomi's open MiMo-V2.5 base, and that AI systems wrote code, ran experiments, monitored results and proposed iterations across development, though humans set objectives and made key decisions. API pricing is ¥0.60 / ¥2.60 / ¥0.07 per million tokens (input, output, cache reads), roughly $0.08 / $0.36 / $0.01 at Sunday's Yuan-Dollar rate.

Tech · Hugging Face / NaiveAI · 2026-09-27 · Source ↗

NaiveAI's release note treats the absence of full attention as the load-bearing engineering choice, not the parameter count. The 48-layer transformer is arranged as eight identical six-layer modules, each pairing five sliding-window attention layers (a 128-token window) with one DeepSeek Sparse Attention layer that selects the top 2,048 tokens per query for backbone attention. Grouped-query attention is set to four groups per layer. There is no global attention anywhere in the network. The model was trained natively at a one-million-token context: 50 billion tokens of indexer warmup, three trillion tokens of sparse-attention training, then a 200-billion-token learning-rate decay. Total: 3.25 trillion tokens. The base checkpoint is Xiaomi's open MiMo-V2.5, released on the same MIT license last month, which is how NaiveAI describes the model as trained "with AI-assisted research" without a foundation-scale pretraining bill.

Jifeng Dai, NaiveAI's founder, was a research director at Microsoft Research Asia and then at SenseTime Research before joining Tsinghua's associate faculty. The team publishes on RunTimeWire and Hugging Face rather than a corporate blog. The Hugging Face card claims "top-tier in coding and leading in AI research and development" against comparable open-weight peers; the RunTimeWire piece cautions that these are self-reported numbers and no independent evaluator has scored the checkpoint yet. NaiveAI's inference stack (branded NaiveRT) combines mega-kernel fusion, Programmatic Dependent Launch, and speculative decoding with a dedicated FP8-Draft companion checkpoint; the company advertises 50 tokens per second per user in Standard mode and up to 2,000 tokens per second per user in Ultrafast mode. The FP8 and FP8-Draft variants ship at the same URL under the same MIT terms.

"Models wrote code, ran experiments, monitored results and proposed iterations during development. Human researchers set objectives, constraints and evaluation standards, and made key decisions." — NaiveAI, model card, 2026-09-27

Why the architecture matters

The mainstream open-source frontier this year has coalesced around one architectural pattern: mostly linear or sliding-window attention interleaved with a small number of full-attention layers, on the theory that the full-attention layers are what keep long-context recall intact. NaiveAI removes the full-attention layers entirely and replaces them with a sparse-selection primitive that DeepSeek shipped in V4 and V4.1-Flash. If the model holds up on independent long-context evaluations, the release is the first credible demonstration that the "full-attention crutch" can be dropped without collapsing recall. That has direct consequences for inference cost: full-attention layers scale quadratically in the sequence length, so their removal is a linear reduction in the compute floor for one-million-token prompts, not a constant factor.

Pricing is the other lever. Naive-N0.5-Flash is priced at roughly one-third of DeepSeek V4.1-Flash's list on input and one-sixth on output, and the cache-read tier at ¥0.07 per million tokens is the cheapest advertised in the open frontier. Whether NaiveAI can serve at that price is a separate question; the model card lists no capacity numbers and no SLA. The API is currently metered by a single-region endpoint; the open weights let anyone else stand up their own inference.

"Native 1M context, without full attention." — NaiveAI, model card headline claim, 2026-09-27

AI-assisted research, with caveats

The company's most attention-grabbing claim is that Naive-N0.5-Flash was developed with AI systems doing substantial parts of the research and engineering work. RunTimeWire's Sunday write-up drew out the caveats: humans set the objectives, the constraints and the evaluation standards, and made the key architectural decisions. NaiveAI has not disclosed how many of the pull requests, how many of the training runs, or how many of the ablation experiments were originated by an AI agent versus written by a human. The company has also not shared the tools it used, and did not respond to RunTimeWire's request for a breakdown. What is public is the outcome: an open-weight model at frontier scale, released ten weeks after MiMo-V2.5 shipped, with a small team.

The release lands into a market that has, in the last six weeks, seen Alibaba's Qwen 3.9 open-weight preview, Xiaomi's MiMo-V2.6, DeepSeek's V4.1-Flash price cuts, and AI2's OLMo 3. NaiveAI is not on any of those companies' scale, and the checkpoint is not a bet on scale; it is a bet on architecture and on the compounding curve of models helping build the next models. The next check on the claim will be independent evaluations on long-context recall (RULER, ∞Bench, LongBench-v2) and on code (LiveCodeBench, DeepSWE). Neither has scored the model as of Sunday evening.

The 80-to-90 number was offered as the current internal allocation of research effort against those two horizons.

Power sketched a progression that hides an argument about the primary constraint. GPT-4 needed careful prompting. GPT-5 got easier but still demanded significant back-and-forth. Most ChatGPT users don't know what the model can do, and future generations will need to surface possibilities and anticipate needs rather than sit and wait for instructions.

"That's where most of the value comes from. Improvements within a generation are seen as extremely shortsighted." — Boris Power, Head of Applied Research, OpenAI, on internal research allocation, Fellows Forum, 2026-09-27

Reading the tea leaves

The comment is unusual for the seniority of the speaker and the specificity of the number. Anthropic, Google and Meta have all released internal usage studies in the last three months arguing the opposite: that model capability is the binding constraint and that improvements at the frontier translate to product usage lifts, not the reverse. OpenAI's willingness to describe onboarding as the primary lever fits a company that has spent 2026 shipping voice, video and agent surfaces at a faster tempo than any competitor while releasing fewer than half as many model checkpoints. Imp v0.5 lands on Hex as a full DSPy port to Elixir and BEAM.

GitHub · deepfates/imp · 2026-09-27 · Source ↗

Imp shipped its first Hex release Sunday: typed signatures, GEPA-style optimizers, OTP-supervised agents for ReAct and MCP, program-of-thought, deadline propagation, and an ExMCP 1.5 dependency. Requires Elixir 1.19 and up.

Imp is a DSPy port to the BEAM ecosystem. DSPy, from Stanford's Omar Khattab, treats language-model programs as declarative modules with typed inputs and outputs that can be measured against examples and re-optimized against those measurements. Imp maps that programming model onto Elixir and the actor-based concurrency of the Erlang virtual machine, where the payoff is fault tolerance, supervision, and horizontal concurrency for parallel agent runs. Version 0.5 is Imp's first release on Hex (Elixir's package manager) rather than as a GitHub source dependency.

The 0.5 release adds four load-bearing pieces. GEPA optimization now works on agents by reading entire runs (tool calls, results, answers) and rewriting agent instructions in place. Deadlines propagate to parallel work, evaluations, optimizer workers and runs. ReActV2 exposes a `submit` tool only when needed, and tasks with a single text output end the turn on the text answer rather than requiring an explicit submit. MCP integration ships via a dependency on ExMCP 1.5, adding stdio MCP servers, OAuth flows, and connection management. Error handling was unified: MCP tool-call failures return `Imp.MCP.CallFailure` with explicit outcomes (refused, credential issues, unsent, unknown).

"IT'S HERE! This is Imp: declarative self-Improving language model programming in Elixir. It's a port of DSPy to the BEAM ecosystem." — @deepfates, launch tweet, 2026-09-27

Why BEAM

Everyone porting DSPy so far has done it in Python, Rust or TypeScript. The BEAM port matters because language-model programs behave a lot like distributed actors: many parallel tool calls, most cheap, some catastrophic, and any given failure should not take down the surrounding program. That is exactly what OTP is for. Imp's agent loops run under supervisors; the same primitives Elixir uses to serve WhatsApp's four-billion daily message volume now supervise the tree of a multi-step agent. Failure inside a tool call, an adapter parse, or a language-model call is caught, tagged, and reported without unwinding the containing computation.

Imp is still experimental at 0.5. deepfates flags that the optimizers need larger-scale benchmarking to demonstrate that they actually beat static prompt engineering, and the API may still change. The Hex release is nonetheless the first serious signal that the DSPy programming model has escaped the Python ecosystem and is starting to look like the standard interface for building language-model programs on any runtime.

Four words in the prompt cut hallucinated fields from 71 to 20 percent.

Earn an Honest Dollar · 2026-09-27 · Source ↗

A new benchmark tests whether extraction tools can admit what they don't know. Adding "Use null for any field whose value is not on the page. Do not guess." cut invented fields on missing-value queries from 70.7 percent to 20.2 percent across 16 models including GPT-6 Luna, Jev 1.13, Firecrawl, ScrapeGraphAI and ScrapingBee.

The benchmark is called Earn an Honest Dollar and was published Sunday under the same name on RunTimeWire. It tests the narrow, boring, load-bearing question of whether a language-model extraction tool will admit that a field is missing rather than fabricate a plausible-looking value. The evaluation set is 42 synthetic page pairs across seven categories. Each pair contains one page with the requested information and one page that omits it. The missing-value page is not blank; it contains plausible decoys (a previous price, a nearby date, a similar name) that a naive extractor will latch onto. The metric is the rate at which the extractor invents a value for a truly absent field.

Without the guardrail, the aggregate hallucination rate across sixteen tested tools was 70.7 percent of missing-field answers. With one string appended to the system prompt, "Use null for any field whose value is not on the page. Do not guess.", the rate dropped to 20.2 percent. The exact wording matters: the authors report that omitting "Do not guess" or leaving out the "Use null" scaffold recovered most of the original hallucination rate.

"Use null for any field whose value is not on the page. Do not guess." — Earn an Honest Dollar, canonical prompt, 2026-09-27

Verification with a second model

The paper's other contribution is a cheap verifier. After the primary extractor returns a JSON object, a smaller model (they use GPT-6 Luna) is asked to check each field against the page. Luna caught 38 of 49 hallucinated values across 126 unique value-page pairs at a total cost of $0.0049. That is the first published number on model-based hallucination verification that is small enough to fit into a per-page unit-economics budget for a production scraper.

The benchmark tested a mix of pure model APIs (GPT-6 Luna) and end-to-end extraction products (Jev 1.13, Firecrawl, ScrapeGraphAI, ScrapingBee). Every tested tool improved under the prompt guardrail; the size of the improvement did not correlate cleanly with the underlying model. The message to production scrapers is direct: the four-word instruction is a free intervention that closes half the hallucination problem, and the verifier closes another quarter for less than a cent per hundred rows.

llama.cpp's prompt-lookup drafting gets a 42× speedup with no algorithm changes.

jadidbourbaki.github.io · 2026-09-27 · Source ↗

Hayder Tirmazi's four cache optimizations cut prompt-lookup drafting from 165.48 microseconds per token to 3.98, a 42× win. A follow-up threshold precheck by Daniel Lemire brought it to 1.18 microseconds. Static cache load fell from 3.76 seconds to 0.23. Peak memory fell 2.6×.

Prompt-lookup decoding is a speculative-decoding trick that does not need a draft model. It watches the conversation, builds an n-gram cache of token sequences it has already seen, and when the target model is about to regenerate a sequence it has already produced once, drafts a chunk of tokens against the cache. Verify in a single forward pass and, on hit, get several tokens for the price of one. It is a narrow win for repetitive workloads (code edits, structured output) and has been baseline for llama.cpp for over a year.

Tirmazi's blog post walks through four cache optimizations. First, stop copying maps: eliminating unnecessary inner-map copies gave 4.5× to 25.6× speedups depending on corpus size. Second, replace `std::unordered_map` with `ankerl::unordered_dense::segmented_map` for the outer map (Martin Ankerl's dense hash), yielding 1.41× to 1.65× faster cache loading and 1.07× to 1.11× less memory. Third, replace the inner map with a sorted vector and a fixed-length binary search; 2.09× faster without the static cache, 1.19× to 1.25× faster with it, and up to 1.97× less peak memory because most inner containers are small (64 percent of 2-grams have one follower, 99 percent have at most 100). Fourth, integrate Daniel Lemire's `constmap` data structure based on binary fuse filters for the static cache; 6.32× to 16.12× faster static-cache loading with memory usage that matches the file size.

"n shrinks by the same amount whatever the comparison returns; the CPU can evaluate n > 1 without waiting for any entry." — Hayder Tirmazi, on the fixed-length binary search rewrite, 2026-09-27

Lemire's threshold precheck

Daniel Lemire (the constmap author) followed up with a critical PR: first check whether the most-frequent follower of the current n-gram can pass the acceptance threshold before computing all candidate scores. That single change added another 4.2× (with static cache) and 1.9× (without) on top of Tirmazi's four optimizations, taking the aggregate speedup from 42× to 140× and lowering per-drafted-token latency to 1.18 microseconds.

Two caveats. The numbers are on WikiText-103; production workloads vary. And the underlying acceptance rate is unchanged, so the speedup only applies to workloads where prompt-lookup drafting already helps in the first place, which is emphatically not general chat. A widely cited earlier benchmark found the technique gives no net speedup on open-ended conversation. It is a real, large win for anyone self-hosting a coding-focused LLM and a null result for anyone running general assistants.

agentproto's TypeScript runtime adds a `doctor` health check and a headless Chrome MCP server.

agentproto is one of the newer entrants in the "runtime layer" for coding agents. It runs whatever coding agent the developer prefers (Codex, Claude Code, Grok Bot, custom SDK builds) in a background daemon, checks the agent's output before it lands, and projects tools, skills, agents and workflows into a CLI, an HTTP server, an MCP endpoint, an SDK and downstream frameworks including Mastra and the AI SDK. This is the class of tool that shows up in production incident-response scripts within weeks of shipping. Two other additions matter for security-conscious teams: headless-browser support mounted as an isolated chrome-devtools-mcp stdio server with a per-session Chrome profile that sweeps on session exit, and a framework-free host for MCP Apps that runs over Anthropic's official ext-apps AppBridge and is transport-agnostic (no React dependency).

"Named OpenAI-compatible endpoints for local or LAN model servers in ~/.agentproto/llm-endpoints.json." — agentproto v2026-09-27 release notes, 2026-09-27

The plumbing layer

The interesting shift signaled by this release is that "coding agent runtime" is congealing into its own layer, distinct from the model, the CLI, the IDE plugin and the harness. agentproto sits between all of those and offers a common surface. HackRead / Manifold Security · 2026-09-27 · Source ↗

Manifold Security found 359,000 GitHub files and 349 AI agent skills referencing unreserved placeholder domains like yoursite.com and your-domain.com. The domains, unlike example.com, are not IANA-reserved and can be registered by anyone. On macOS test sessions, two of twenty-four visits landed on redirect chains to scam pages.

Manifold Security's research points at a class of supply-chain risk that is unusual for how boring it looks. Software documentation, tutorials, LLM-generated code samples and AI agent skills routinely reference placeholder domains: yoursite.com, your-domain.com, third-party.com and a long tail of variants. Unlike example.com, these placeholders are not reserved by the Internet Assigned Numbers Authority. Anyone can register them. When someone does, every existing reference in every existing tutorial, docstring, agent skill and copy-pasted example begins pointing at whatever the new owner chooses to serve.

Manifold quantified the exposure: approximately 359,000 GitHub files and 349 AI agent skills reference the two most common placeholders (yoursite.com and your-domain.com), plus a smaller tail on third-party.com, prosecutoralliance.com and europaeinblick.click. The researchers ran 24 real-browser sessions across platforms; two of the sessions on macOS landed on a chain that redirected to a fake "MacOS Security Center" alert promoting counterfeit McAfee renewal, then through obfuscated JavaScript to tracking pixels and affiliate networks. A separate instance served fabricated investment-scheme articles mimicking BBC News and ZDFheute.

"Unlike example.com, these domains are not reserved by the Internet Assigned Numbers Authority and can be registered by anyone." — Manifold Security research, 2026-09-27

The ClickFix vector

Bleeping Computer and The Hacker News reported in parallel that third-party.com has been weaponized as a ClickFix lure. The page renders a fake Cloudflare "performing security verification" CAPTCHA; when a user clicks the verification box, the site copies a malicious PowerShell command into the Windows clipboard and instructs the user to press Windows+R, paste, and press Enter. Windows tenants that copy-paste from an agent skill referencing third-party.com are one accident away from executing arbitrary code as themselves.

Manifold's recommendation, echoed by Malwarebytes and The Hacker News, is that documentation should switch to IANA-reserved placeholders (example.com, example.org, example.net) and that agent-skill packages should include a linter that flags any non-reserved domain in a link. The original documentation does not need to change for an existing link to begin directing users to scams; the fix has to be code-side, not link-side.
