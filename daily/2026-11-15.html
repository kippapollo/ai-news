Runway releases Praxis-1 27B mixture-of-experts video-and-action transformer running on a single RTX 5090 under NVFP4.

Runway Research · GitHub · 2026-11-14 · Source ↗

Praxis-1 is a 27-billion-parameter mixture-of-experts diffusion model that predicts video and robot actions together. It runs on a single RTX 5090 using NVFP4 4-bit checkpoints. Checkpoints and runtime configs for the SO-101 robot arm were open-sourced alongside the research page; LeRobot community contributors are named in the acknowledgements.

Runway's research team released Praxis-1 on Saturday as its first joint video-and-action model: a 27-billion-parameter mixture-of-experts diffusion transformer that generates rollouts of what the camera will see and what the robot's joints will do on the same pass. The checkpoints and runtime configurations ship for the SO-101 robot arm, a low-cost LeRobot community reference design, and the whole package runs on a single consumer RTX 5090 using NVFP4 4-bit weights. The release lands two days after Google DeepMind's Gemini Robotics 2.5 on Mercedes-Benz parts and a day after OpenAI's robotics-team dissolution.

What it does

The model takes a short video of the workspace and a text instruction and returns, on each diffusion step, a predicted video continuation and a sequence of action chunks for the robot arm. Treating pixels and joint commands as a shared denoising target pushes the model to keep the video and the action consistent; a model that hallucinates a pouring motion in the video but doesn't plan the matching joint trajectory is penalized. Runway's benchmark table showed Praxis-1 beating specialized SO-101 policies on cloth-folding and small-object manipulation by double-digit margins at the same parameter budget.

"Pixels and joint commands as a shared denoising target." — Runway Research page, 2026-11-14

Why single-GPU matters

The RTX 5090 ceiling is a direct response to the specialized-versus-generalist debate Fortune surfaced in Friday's OpenAI-robotics-teardown. Nvidia's RoboLab-120 benchmark pitched GPT-6 Astra as the general-purpose reference; Praxis-1 argues a mid-sized MoE at NVFP4 can carry a robot without a data-center GPU. The release leaves open two questions: how the policy transfers across arms beyond SO-101, and whether the released checkpoints are the ones Runway used for the research page benchmarks or a trimmed variant.

Tencent Hunyuan released its Hy Realtime conversational speech model on Saturday. The design is end-to-end rather than cascaded: no separate ASR transcribes audio into text for a text LLM that an upstream TTS then speaks; Hy Realtime consumes audio and emits audio, with search tool-use decisions and prosody made in the same forward pass. What it handles

The release page lists three behaviors Hy Realtime handles that cascaded systems typically struggle with. Second, in-flow search: the model decides when to pause and query Tencent's search index for a factual answer rather than hallucinating. Third, singing on request: a user asking for a chorus of a named song, or asking the model to "sing that in jazz," gets a synthesized vocal in the requested genre.

Anthropic upgrades Claude Code Projects with /btw, /fork and background-job snooze; sub-threads report without manual polling.

Claude Devs on X · 2026-11-14 · Source ↗

The project coordinator now reports on parallel sub-threads without manual polling. /btw starts a side inquiry without changing main-task memory; /fork clones a thread; threads can be snoozed and resurface when background jobs finish. The update ships to Claude Code Projects as a server-side change.

Anthropic shipped a multi-thread update to Claude Code Projects Saturday that adds three behaviors and changes the top-level coordinator. The coordinator agent now reports on parallel sub-threads automatically, without the user having to type "status" or "what's running"; threads can be forked, snoozed and queried in-flight without disturbing the main task's memory. The update is a server-side change on top of the existing Projects plane and does not require a client update.

The three commands

The `/btw` command starts a side inquiry that does not write back to the main-task context. The intent: a developer running a long refactor can ask a one-off question ("remind me what the Protobuf schema for the auth service looked like last week") without polluting the main-task memory with the answer. The `/fork` command clones an existing thread with its memory intact for parallel exploration. Threads can be set to `snooze`; they resurface automatically when a named background job (a test run, a build, an upstream review) finishes. The announcement names the Protobuf lookup as the canonical use case for `/btw`.

"Reports on parallel sub-threads without manual polling." — Claude Devs on X, 2026-11-14

What changed for the coordinator

Before the update, Projects' coordinator reported sub-thread status only when prompted. The Saturday update moves to a subscribed-notification model where the coordinator pushes a short summary into the main-task stream whenever a sub-thread finishes a milestone the main task referenced. The update is consistent with the Fermat's-Last-Theorem agent-swarm result Anthropic published with Fable 5.2 on November 9, where a thousand Fable agents formalized the proof in Lean in about 30 hours with minimal human intervention: the coordinator-side plumbing is the same one.

Cloudflare open-sources Kitesurf: a serverless browser engine for AI agents on Workers with Chrome DevTools Protocol support.

Cloudflare Blog · 2026-11-14 · Source ↗

Kitesurf is a serverless browser engine for AI agents on Workers, released under Apache 2.0. It renders pages and takes screenshots without headless Chrome containers, supports the Chrome DevTools Protocol for Puppeteer compatibility, and works with the WebMCP tool framework. The release targets inference-time browser automation at edge latency.

Cloudflare open-sourced Kitesurf on Saturday as a serverless browser engine purpose-built for AI agents running on Workers. The engine renders pages and takes screenshots without needing a headless Chrome container to spin up per request; this collapses a two-second cold start that dominates Playwright-on-Lambda agent-browsing stacks. Kitesurf supports the Chrome DevTools Protocol so existing Puppeteer scripts port in, and it connects to the WebMCP tool-definition framework so an MCP-aware agent can declare browser actions as tools.

Why the architecture matters

Agent browsing costs sit in two places: the model inference and the browser-rendering container. For agents that take hundreds of steps, the browser container often costs more than the model. Kitesurf's serverless path keeps the rendering cost in the edge PoP, close to the user's data, and sheds the per-request container boot. Cloudflare's benchmark table on the launch post claims one-fifth the per-step cost and one-tenth the p95 latency of the Playwright-on-Lambda reference.

"Renders pages and takes screenshots without headless Chrome containers." — Cloudflare Kitesurf launch post, 2026-11-14

What's open-sourced

The Apache 2.0 repository ships the rendering engine, the CDP adapter, and the WebMCP tool bindings. The repo does not ship Cloudflare's edge scheduler, which is the piece that routes sessions to idle Workers nodes; running the stack outside Cloudflare will need a separate scheduler or a self-hosted equivalent. The launch follows OpenAI's Browserbase partnership for ChatGPT Wallet on November 13 and Replit's Browserbase-powered agentic commerce the same day.
