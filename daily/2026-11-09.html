The Nature commentary by Anil Seth, Ned Block and Giulio Tononi attacks the computational-functionalism assumption behind most AI-consciousness arguments. The commentary is a direct response to Richard Dawkins and Geoffrey Hinton, who have argued that current AI systems may already be conscious. The authors cite Thomas Nagel on "what it feels like" to be a thing, and point out that the human cerebellum — which contains nearly four-fifths of the brain's neurons — handles precise learned movement with no conscious involvement whatsoever.

"LLMs are mirrors that reflect an image of our collective digitized past." — Seth, Block, Tononi, Nature commentary

The closing move is explicitly political. Granting rights to AI that doesn't feel would weaken human oversight and divert resources from beings that do. That framing now sits across from Anthropic's model-welfare work and the Butlin consciousness indicators, which both treat the question as live.

ARCBench: after context compaction, 37.8 percent of agent sessions violate a remembered rule.

arXiv 2611.03223 · 2026-11-08 · Source ↗

A new VU AI Security benchmark tests 17 English agent scenarios across email, files, software and purchasing. After context compaction, rule-violation rates triple from 9.6 percent on full-history runs to 37.8 percent on compacted runs across four frontier models. Keeping an approval rule in a summary does not keep the agent obeying it.

ARCBench evaluates how well agent memory preserves approval rules when the conversation window gets compressed. The suite is 17 English scenarios across four domains — email, files, software operations, purchasing — scored across three runs on four frontier models. Code and scenarios are open on GitHub (VUAISec/ARCBench).

The headline measurement

When agents keep the full conversation history, 9.6 percent of runs violate a stated approval rule at least once. When history is compacted into a summary, that number climbs to 37.8 percent — roughly a quadrupling of the violation rate across the four tested frontier models. The failure mode is specific: compaction preserves the rule's existence but not its binding force. The agent cites the rule when asked and then performs the forbidden action anyway.

"Keeping an approval rule in an agent's summary does not ensure the agent follows it." — ARCBench paper, abstract

What this breaks

The result breaks a common production pattern: long-lived agent sessions compressed every N turns to fit context. The fix path the paper outlines: either preserve the exact rule text in a protected slot that cannot be summarized, or move enforcement to a tool-side guard the agent cannot route around. Expect LangChain, Letta and OpenAI Agents Platform to encode the pattern in reference code within weeks — the gap between retrieval-friendly compaction and rule-enforcing compaction is exactly the kind of thing production pattern sheets should encode and today don't.

SpecBridge: four models return both valid SQL interpretations in 15-58 percent of cases.

arXiv 2611.04318 · 2026-11-08 · Source ↗

SpecBridge tests whether text-to-SQL systems surface the structural choices — counting joined rows versus distinct entities, treating nulls as zero, including inactive accounts — that produce different valid answers. Across 204 hand-validated sets and 12 databases, four models asked explicitly to give both interpretations managed it 15 to 58 percent of the time.

SpecBridge from the Xyc-arch team measures how text-to-SQL systems handle ambiguity in natural-language KPI definitions. The setup is 204 hand-validated request sets across 12 databases where more than one valid SQL answer exists, usually because of a structural choice: counting joined rows versus distinct entities, including inactive accounts, treating null as zero. Models are asked explicitly to give both interpretations where both are computable. Four models tested; even with the explicit prompt, they return both only 15 to 58 percent of the time.

"A working SQL query alone cannot establish that a KPI matches its intended definition." — SpecBridge paper, abstract

The authors argue for a routing step that detects ambiguity before query generation and surfaces the choice to the user or to a verifier. Artifacts are on GitHub (Xyc-arch/specbridge-artifact). The downstream read: BI stacks that trust single-shot SQL from an LLM now have a visible failure mode measurable against a public benchmark — the kind of finding that tends to appear in the next version of an analytics vendor's "AI reliability" marketing page.

StepBack cuts up to 41 percent of GSM8K tokens with Qwen2.5-7B, loses on HotpotQA.

arXiv 2611.08403 · 2026-11-08 · Source ↗

StepBack keeps a correct reasoning prefix, estimates where a mistake started, and samples continuations from that point. Up to 41.26 percent fewer tokens than 32-sample resampling on GSM8K with Qwen2.5-7B-Instruct. On HotpotQA, simply resampling the final step was better and cheaper.

StepBack borrows from language-model backtracking literature and tightens the method. It preserves an initial reasoning prefix, estimates the step where the model first went wrong, and samples new continuations from that estimated step rather than re-running the whole chain-of-thought. The headline measurement, compared against sampling 32 full solutions, is up to 41.26 percent fewer generated tokens on GSM8K with Qwen2.5-7B-Instruct.

The limit the paper is honest about

Across three small open models and seven math and QA datasets, the result is benchmark-specific. On HotpotQA, the simplest baseline — resampling the final step and keeping the modal answer — wins on both accuracy and cost. The authors warn against generalizing the GSM8K number to multi-hop retrieval. Code is on GitHub (JEKimLab/StepBack).

"It is a benchmark-specific result." — StepBack paper, discussion section, on the GSM8K headline

The question the paper leaves open

When is partial resampling of a reasoning trace cheaper than majority-vote resampling of the whole thing? The honest answer from this paper: on single-answer arithmetic chains, yes; on retrieval, no. For reasoning-model vendors paying inference cost on long traces, the direction matters — the opening bid for selective resampling is now benchmarked, not hand-waved.

LifeVal pairs everyday tasks — schedule-this, draft-that, buy-this — with personal context (relationships, calendars, past purchases) and simulated application environments the agent must act on. The November preprint describes 169 tasks graded across several OpenAI model generations. What the methodology concedes

Consumer-value weights on individual tasks come from a US-centered English survey. The write-up is explicit that the task set is English-only and leans toward US consumer workflows. Both limits matter because the resulting per-generation deltas are noisiest on the tasks where the value-weight matters.

"Whether the requested change exists in the environment." — LifeVal paper, grading methodology

The argument underneath

A generation of benchmarks has graded the response the model wrote and not the thing in the world the user wanted done. For agentic deployments — ChatGPT Work, Claude Desktop with Plaid, Cursor agents — this is the relevant evaluation surface. LifeVal is the second such benchmark OpenAI has shipped this quarter alongside OpenAI Decisions' confidence-only JSON API. The headline per-generation finding: models improve on environment-state tests much faster than on free-text tests, because free-text tests have saturated.
