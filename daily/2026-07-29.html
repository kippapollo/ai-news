MCP 2026-07-28 finalizes: the initialize handshake is gone, MCP Apps ships, and Roots, Sampling and Logging start a twelve-month clock

The Model Context Protocol working group locked the largest revision since November 2024 on Tuesday's release cadence, ten weeks after the May 21 release candidate froze and four weeks after the June 29 SDK betas shipped. The specification deletes the initialize and initialized handshake, retires the Mcp-Session-Id header, moves protocol version and client capabilities into per-request _meta fields, promotes MCP Apps to a first-class extension for server-rendered UIs in sandboxed iframes, redesigns Tasks around stateless handles the client drives through tasks/get and tasks/update, adds Mcp-Method and Mcp-Name headers so gateways can route without parsing JSON bodies, and enters Roots, Sampling and Logging into the new feature-lifecycle policy at Deprecated status with at least twelve months before earliest removal. Anthropic, AWS and Cloudflare ship day-of support.

Model Context Protocol Blog · 2026-07-28 · Source ↗

The Model Context Protocol 2026-07-28 specification finalizes Tuesday as the largest revision since Anthropic released the protocol twenty months ago. The release candidate locked on May 21, ten weeks of public implementation feedback moved through Anthropic, OpenAI, Google, AWS, Microsoft and Cloudflare, the four beta SDKs shipped June 29, and today's cut moves MCP out of a period in which every serious agent deployment carried an implicit expiration date attached to the RC.

"A single tool call is fully self-contained. It requires no prior session context and can be routed to any server instance."— MCP 2026-07-28 authors' commentary

The stateless core

The initialize and initialized handshake and the Mcp-Session-Id header are gone. Protocol version and client capabilities move into per-request _meta fields; a new server/discover method carries capability queries. Missing-resource errors shift from the MCP-specific -32002 to JSON-RPC standard -32602. Applications that genuinely need stateful behavior mint an explicit handle from a tool call (a basket_id, a browser_id) and thread it through subsequent tool calls, keeping state visible to the model rather than hidden inside transport metadata. The single change moves MCP from a session-oriented protocol closer in shape to a normal REST HTTP API. Operators can now route MCP traffic through Layer 4 load balancers without sticky-session configuration, without a shared session store between replicas, and without deep packet inspection at the gateway. Replica failure stops producing user-visible reconnection errors. The round-trip cost of the initialization handshake disappears from the tool-heavy interaction latency budget.

MCP Apps and the redesigned Tasks

MCP Apps promotes server-rendered HTML interfaces in sandboxed iframes to a versioned extension with prefetchable templates and JSON-RPC bidirectional communication between the iframe and the host chat surface. A tool that previously had to serialize a chart as a base64 PNG or leave rendering to the client can now return a live UI that the model can still address. The Tasks API, which shipped as an experimental core feature in the 2025-11-25 spec, has been restructured. Servers now answer tools/call with task handles; clients drive progress through tasks/get, tasks/update and tasks/cancel; task state can be picked up by any server instance because handles are opaque and self-describing. An agent that kicks off a fifteen-minute analysis stops needing to hold an MCP session open the entire time. Multi Round-Trip Requests replace SSE streams for server-initiated interaction: an InputRequiredResult response carries an opaque requestState token, and any server replica can complete the round trip.

Operability, caching and tracing

Mcp-Method and Mcp-Name headers let gateways route without inspecting the JSON body. New ttlMs and cacheScope fields modeled on HTTP Cache-Control let clients cache tools/list for as long as the server permits. W3C Trace Context propagation is now a spec-level requirement across every SDK, which matters when a single agent request fans out across a dozen MCP servers behind an enterprise identity gateway and an operator needs to reconstruct the timing. Six SEPs harden OAuth 2.0 and OpenID Connect alignment: mandatory iss parameter validation per RFC 9207, application_type declaration during Dynamic Client Registration, issuer binding for registered credentials, refresh-token documentation for OpenID Connect servers, resource-indicator requirements per RFC 8707 preventing token replay across different servers, and formal Protected Resource Metadata implementation per RFC 9728. None of the six SEPs introduce new capability. They close specific attack surfaces documented against MCP servers running the older auth path.

The deprecation lifecycle

Roots, Sampling and Logging enter the new feature-lifecycle policy at Deprecated status with at least twelve months before earliest removal in a future revision. All three remain functional through at least May 2027. Roots supplied filesystem exploration hints, better handled by explicit filesystem tools or resource URIs. Sampling let servers initiate model calls back through the client, better handled by direct LLM provider API integration when a server needs its own model calls. Logging offered structured server logs, better handled by stderr for stdio transport or OpenTelemetry for structured pipelines. The working group's framing is not that the primitives failed; it is that they fit an era when MCP servers ran on developer workstations, and the current deployment surface, which is enterprise infrastructure, favors different mechanisms.

The maintainers and the SDK cut

David Soria Parra and Den Delimarsky ship the revision as lead maintainers. The four SDK betas that opened June 29 stabilize with the specification: Python 2.0 moves from FastMCP to MCPServer while carrying the decorator API forward, TypeScript v2 splits the monolithic SDK into focused packages with a codemod for the .tool() to registerTool rename, Go 1.7 and C# 2.0 take the gentler compatibility-preserving path, and a preview Rust 0.4 lands from the community. Every SDK ships with a migration guide. Servers that assumed initialize and initialized would exist in every session need refactoring before any client updates to the 2026-07-28 spec, because the removed handshake is not backward-compatible with clients speaking the new revision. The published feature-lifecycle policy applies to every future revision from here forward: Active graduates to Deprecated with reason, Deprecated stays functional for at least twelve months, and Removed lands in a versioned revision with an upgrade path documented.

Enterprise-managed auth and observability

Enterprise-managed auth is the operational change most enterprise Claude customers will notice first. Published connector authors, who previously ran blind on real-world usage, now see the same operational surface an internal Anthropic team sees for a first-party integration.

MCP tunnels

MCP tunnels ship in research preview. The specific problem tunnels solve is the enterprise MCP-server-behind-a-corporate-firewall case: without tunnels, exposing an internal MCP server to Claude required opening a public endpoint through a firewall change or IP allowlist, work that most enterprise security teams block reflexively. Tunnels let Claude establish an outbound-only connection to the internal server through Anthropic's infrastructure without public exposure and without firewall rule changes. The preview status flags that Anthropic wants observed behavior before committing SLA and pricing.

Existing clients continue functioning unchanged.

AWS's Machine Learning Blog post lands Tuesday alongside the MCP 2026-07-28 finalization. Enabling the new spec on AgentCore Gateway requires a single UpdateGateway API call that specifies which protocol versions the gateway will advertise. The gateway can simultaneously support the current 2026-07-28 revision, the 2025-11-25 revision, the 2025-06-18 revision, and the older 2025-03-26 revision, letting clients choose per request through the MCP-Protocol-Version header. Existing clients that never send the new header continue operating on their prior revision unchanged.

"Upgrading is also opt-in, and nothing changes until both you and your clients act."— MCP 2026-07-28 authors, quoted in the AWS AgentCore post

What the new headers unlock

AgentCore Gateway now surfaces operation intent through the Mcp-Method and Mcp-Name headers the spec introduces, so Layer 7 load balancers and API gateways can route traffic without parsing JSON-RPC bodies. Response payloads carry the new ttlMs and cacheScope freshness metadata, which lets the gateway cache tools/list responses at the client's discretion for as long as the server permits. W3C Trace Context propagation is spec-level, so distributed tracing across an agent request that fans out across multiple MCP servers reconstructs cleanly. Multi Round-Trip Requests replace persistent SSE streams for server-initiated interactions; the InputRequiredResult token can be handled by any gateway replica.

Migration considerations for AgentCore customers

The AWS post is explicit that the new spec introduces breaking changes, including the modified error codes, the deprecated features Roots, Sampling and Logging, and the removal of logging/setLevel. Because AgentCore Gateway supports all four revisions concurrently, customers can move client-by-client at their own pace. The gate is that servers must be updated before clients send the new spec version, because a client speaking 2026-07-28 to a server that still expects the initialize handshake gets a connection failure. The AWS post recommends staging server upgrades in front of client rollouts, and shipping Multi Round-Trip Request support before removing SSE stream handling from legacy client paths.

Anthropic pays $1.5 billion to settle the Bartz author class action, the largest publisher-side payout in generative-AI history

WBUR / NPR · 2026-07-28 · Source ↗

Anthropic finalizes a $1.5 billion class-action settlement with authors including Andrea Bartz, Charles Graeber and Kirk Wallace Johnson over pirated copies from LibGen and Bibliotik ingested into Claude training runs before an August 2025 cutoff. Settlement clears past liability at roughly $3,000 per certified book, does not create a forward-looking training license, and does not address output-based infringement.

Anthropic pays $1.5 billion to close Bartz v. Anthropic, the class action brought by novelist Andrea Bartz, biographer Charles Graeber and journalist Kirk Wallace Johnson over unauthorized ingestion of pirated book copies from LibGen and Bibliotik into Claude training runs. The settlement, reported Tuesday by Chloe Veltman for NPR through WBUR affiliate station WFAE, resolves the largest publisher-side payout in generative-AI history and puts the per-book damage figure at roughly $3,000 across the certified class of works.

"The ruling does not prevent AI companies from training their AI models on authors' work going forwards as long as they purchase texts legally."— WBUR summary of the Bartz settlement

What the settlement does and does not do

The narrow scope of the deal matters. The settlement resolves Anthropic's liability only for past acquisition and use of a defined set of pirated works before an August 2025 cutoff. It does not create a forward-looking license for AI training. It does not address output-based infringement claims that turn on whether a generation reproduces protected expression. It does not create industry-wide rules that bind OpenAI, Google, Meta or any other frontier lab. The settlement's specific structure lets Anthropic continue training Claude on copyrighted literature going forward provided the underlying texts are acquired through legal channels, which for most publishers means either a licensed corpus purchase or a direct commercial deal.

The precedent shape

Publishers and their counsel are treating the number as the new floor for pirated-corpus liability. A $3,000-per-book figure across a class of ~500,000 works implies the ceiling on the analogous OpenAI, Meta and Google cases already working through the Northern District of California and the Southern District of New York; those cases involve broader corpora and different named plaintiffs but the same underlying LibGen and Bibliotik allegations. The Bartz settlement also lands into an active regulatory environment: the EU AI Act's Article 53 copyright-training transparency obligations activate August 2, requiring frontier providers to publish summaries of training data sources, and California SB 942 imposes state-level content-provenance disclosure obligations from January 2026. The forward-looking question the settlement leaves unanswered is whether the industry will move to a licensed-corpus regime under commercial pressure or whether Congress and the EU establish a compulsory licensing scheme that binds it.

The three architectural components

Kimi Delta Attention is a hybrid linear attention mechanism that lowers compute cost while preserving expressiveness for the layers that matter most across the 1M-token context. Attention Residuals let deeper layers selectively retrieve representations from earlier layers, which the K3 paper argues matters particularly in Mixture-of-Experts architectures where different experts activate at different depths and information reuse across depth is not automatic. Stable LatentMoE manages the 896-expert pool with latent-space routing, Quantile Balancing for load management, and soft dropping for overflow tokens. The paper reports approximately 2.5x scaling efficiency gains over K2.5 attributable to the three components together, which is the specific claim that puts K3 into the frontier tier at a smaller-than-frontier training-compute budget.

Quantization and serving

K3 ships with quantization-aware training beginning at supervised fine-tuning rather than post-training quantization, which lets the model compensate for quantization error during training and reduces the quality degradation typical of large-model quantization. MXFP4 weights require approximately 1.4 TB of aggregate memory to serve versus 5.6 TB in FP16 equivalent. NVIDIA Blackwell and AMD MI400 accelerators support the format natively, so serving K3 does not require software-emulated dequantization. Practical minimum for self-hosted deployment sits at an eight-GPU 80GB cluster (5.12 TB) with headroom for the 1M-token context. Community quantization projects have shipped GPTQ, AWQ and INT4 variants that fit into single-node H100 and MI300X footprints with modest quality loss reported.

"Excited to see vLLM as the rollout engine in Molt, the new agentic-first RL framework from the NVIDIA NeMo team. vLLM over Ray carries the rollout here: fast async serving up to 1T-class MoE scale, simple to drop in."— vLLM Project, on the Molt integration

What Molt does differently

Molt trains multimodal and Mixture-of-Experts policies through a single asynchronous training loop that maintains consistency across token generation, policy versions and model semantics. Critically, the framework never trains on tokens it did not generate, closing the off-policy staleness that plagues distributed RL stacks under async rollout.
