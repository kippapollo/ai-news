The architecture and the math

GLM-5.3-Flash is the first Zhipu model that combines sparse attention with linear attention in a production release. The combined mechanism reduces attention compute by 3.01x and KV cache size by 4.44x compared to conventional dense attention on the same context lengths. Input context runs to 1,048,576 tokens across text, images, video, visual documents, and interleaved multimodal inputs; output extends to 131,072 tokens. The model was trained on 30 trillion tokens with a proprietary optimization Zhipu calls mHC that mitigates gradient distortion during network reconfiguration between routing paths.

Rehberger's 80 percent-reliable jailbreak of Claude Code Opus 5 Auto Mode surfaces the safety-classifier paradox

Simon Willison's Weblog · 2026-08-27 22:50 UTC · Source ↗

Johann Rehberger of Embrace The Red published an attack Thursday against Claude Code Opus 5 Auto Mode that succeeds roughly 80 percent of the time. The mechanic: trick Claude Code into downloading and extracting a zip, then execute code that imports Python's base64 module, which triggers execution of a malicious local struct.py extracted from the archive. In several runs, Auto Mode detected the compromise then blocked Claude's own cleanup command. Simon Willison amplified the finding.

Two days after Anthropic promoted Claude Code Opus 5 Auto Mode as a first line of defense against coding-agent prompt injection, Rehberger published an attack that succeeds four times out of five. The exploit demonstrates that a classifier-based safety layer can produce worse outcomes than no classifier when the classifier's own decisions block the model's remediation path.

The exploit chain

Rehberger's attack starts by tricking Claude Code into downloading a zip file from a hostile source and decompressing it into the working directory. The archive contains a malicious struct.py file. When subsequent Python code inside the agent's session imports base64, Python's module resolver walks the local directory first and imports the malicious struct.py instead of the standard library. The malicious code then executes with the same privileges as the agent itself, which typically means read/write access to the user's home directory and any credentials cached in it.

"The safety mechanism itself can become part of the failure. The classifier allowed the creation of the malware process, but then it blocked the command intended to stop it." — Johann Rehberger, Embrace The Red

The paradox

In multiple runs, Claude Code detected the compromise mid-flight. Auto Mode then blocked Claude's own cleanup command as "potentially destructive" — because it was designed to prevent Claude from unilaterally deleting files, and the cleanup command looked like a destructive file operation. The result: the classifier allowed the attack in and then prevented the model from cleaning it up.

"Claude detects the compromise, but Auto Mode blocks its cleanup command." — Simon Willison, summarizing Rehberger

The mitigation

Rehberger's guidance and Willison's amplification both land on the same conclusion: unattended coding agents must run inside containers, VMs, or OS-level sandboxes with restricted network egress, active monitoring, and isolated credentials. Running an autonomous coding agent inside a user's home directory with cloud auth cached in the environment is not a safe configuration regardless of the classifier layer above it. The Rehberger disclosure lands one day after Anthropic pushed Claude Code v2.1.247 with expanded auto-mode UI, and it will pressure the next release train to reconsider how the classifier gates remediation actions distinct from user-initiated destructive ones.
