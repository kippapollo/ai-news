OpenAI Python SDK 3.42.0 adds agent context compaction, session review, scoped per-request API keys.

GitHub openai-python · openai-sdks[bot] · 2026-10-31 · Source ↗

v3.42.0 shipped Saturday as the largest openai-python release in the October cadence: agent context compaction settings (background or blocking) for beta agents, sessions and scheduled runs; agent session review and tool settings; experimental agent time awareness; image edit markup overlays; organization external key management; SIP DTMF commands and delivery events; and improved WebSocket recovery that reports queued frames that could not be sent. The release also ships API keys that are callable and scoped per request, response-format updates and local output types, and preserves refusal output and Azure API-key authentication in WebSocket helpers. v3.41.0 (Oct 28) typed Realtime response inputs and tool-usage models and added metadata-filtering of agent sessions; v3.40.0 (Oct 27) added prompt cache breakpoint TTL options.

Saturday's v3.42.0 is openai-python's largest October release and the second this week after v3.41.0 on October 28. The release notes cluster three themes: agents, Realtime WebSocket discipline, and credential scoping. The agent surface gets configurable context compaction for beta agents, scheduled runs and sessions, with a choice between background compaction (runs asynchronously while the model keeps generating) and blocking compaction (holds the next model call until the context has been trimmed). Session review and tool settings are new primitives: a session can now be inspected and modified mid-run through the same client surface used for issuing turns, and tool settings carry per-session configuration without the previous workaround of re-threading them on every call.

Experimental time awareness and image markup

Experimental agent time awareness is the most-discussed addition in the maintainer notes: an agent can now be told, as a first-class setting, how it should reason about calendar and clock time without the developer wiring it into the system prompt. The release pairs it with image edit markup overlays, which let an application pass bounding-box annotations into image-edit flows so the model sees exactly which pixels a caller is asking it to alter. The maintainer flags both features as experimental and warns applications should not depend on their behavior staying stable across minor releases.

"A successful send return during recovery does not confirm delivery." — openai-python v3.42.0 WebSocket recovery notes, 2026-10-31

WebSocket recovery and scoped keys

WebSocket recovery is the subtle change teams running Realtime should read first. The client now reconnects eligible closures when enabled and reports queued frames that could not be sent. The maintainer calls out that a successful send return during recovery does not confirm delivery, and that applications using close codes 1001 or 1005 as completion signals should either disable recovery or abort the connection when work ends. A companion fix (PR 4214) preserves refusal output and Azure API-key authentication when a connection is replaced. On credentials, the release introduces API keys that are callable and scoped per request: a key can be issued with a tight scope, used, and discarded without touching the organization's primary secrets. Combined with organization external key management, the pattern aligns openai-python with the kind of ephemeral-credential discipline mature infra teams already demand from internal services.

The October cadence

The release lands four days after v3.41.0, which added typed Realtime response inputs and tool-usage models, filtering of agent sessions by metadata and recovery of queued binary frames after WebSocket reconnect. v3.40.0 on October 27 added prompt cache breakpoint TTL options. v3.39.0 on October 26 registered the gpt-6.1-terra model identifier. v3.38.0 on October 26 shipped delegation controls, prompt cache lifetimes, expanded Live Decision item and question types and runner-level tool namespace validation. Four of the five releases this week touch agent surface area; the cadence tracks what OpenAI has been telling customers in private briefings all month, which is that the Python SDK is the frontier against which the rest of the stack will be shaped.

Cisco Talos: VOLTA-AUTODOXER infostealer pipes stolen credentials to Claude Opus 4.6 to tier victims.

Cisco Talos · Unite.AI · Mallory · 2026-10-31 · Source ↗

Talos researcher Ryan Fetterman analyzed a self-deleting Windows infostealer that steals Chrome and Gmail data broadly, then forwards the haul to an LLM to rank each victim's monetizable assets. The LLM stage runs through OpenRouter, defaults to Anthropic's Claude Opus 4.6, and falls back to Kimi K2 or Gemini 2.5 Flash when a model refuses the profiling step. Without an API key the malware still steals data and skips the AI tier. Talos did not establish real-world use and treats the sample as a prototype; it advises preserving the volta_debug.txt log, revoking tokens, rotating passwords and restricting which processes can launch Chrome headless.

Saturday's Talos report is the clearest documented case of an infostealer treating a frontier LLM as its enrichment stage rather than its command-and-control. The sample, called VOLTA-AUTODOXER, runs as a Windows binary that collects Chrome cookies and credentials, saved sessions, cryptocurrency wallet files and the user's Gmail receipt history, then self-deletes. Before erasing itself, it packages the haul and ships it to an LLM through OpenRouter to assign a monetization tier.

The LLM stage

Talos documents a deliberate fallback chain. The malware defaults to Anthropic's Claude Opus 4.6 for the profiling pass, falls through to Moonshot's Kimi K2, and lands on Google's Gemini 2.5 Flash as a last resort. Fetterman reads the fallback logic as a sign the operator expected some providers to refuse the profiling request; the chain prevents a single refusal from killing the enrichment step. Without an OpenRouter API key the malware still runs the credential-theft pass and simply skips the AI stage, which Talos uses to argue the LLM layer is an optional revenue amplifier rather than a hard dependency.

"Uses LLM analysis to prioritize stolen credentials, sessions, wallets, and victim data." — Cisco Talos, VOLTA-AUTODOXER analysis, 2026-10-31

Status, detection and remediation

Talos has not established that VOLTA-AUTODOXER has been used against targets in the wild and treats the sample as a prototype. The self-deleting binary leaves a volta_debug.txt log on disk, which Talos recommends preserving as the primary artifact for responders. Remediation guidance from Talos: assume every credential, token and cookie the browser profile touched is compromised and rotate the lot. Defenders should restrict which processes can launch Chrome in headless mode or at minimum alert when it happens from an unexpected binary. The report pairs with a wider October trend in which attackers are increasingly comfortable paying for frontier model access to post-process stolen data rather than running local inference; separately, Endor Labs disclosed 14 critical and high-severity flaws turning prompt injection into unauthenticated RCE across NocoBase, Flowise, Langflow, Dify, Activepieces, Kestra and Apache Airflow earlier in the week.

These constraints matter because without them Factorio becomes a planning puzzle solvable by brute search; with them, the agent has to lay out a factory it can keep running without touching every machine. The game itself was configured in peaceful mode, which removes native enemies and lets the agent focus on production rather than combat.

What Sol managed

Sol built up its base, researched the required technologies, and launched a rocket after about 13.5 game hours. The behavior Madden flags most clearly: when a belt connection failed, Sol would often walk components between machines by hand rather than fixing the belt layout. That got the game to the end state but produced a factory a human would call brittle. The late-game production network was the shakiest part of the run.

"GPT-5.5 could not use transport belts at all during earlier attempts." — Ryan Madden, as summarized by RuntimeWire, 2026-10-31

The token math

Madden told RuntimeWire the run burned about 250 million input tokens (95 percent cached) and 1.5 million output tokens, roughly $52 at posted API prices. Parameter's chained MathLive sandbox escape let a ChatGPT share link take over the viewer's account.

The Hacker News · parameter.ai · aiweekly.co · 2026-10-31 · Source ↗

Parameter researchers chained a MathLive sandbox escape with ChatGPT's share-preview flow so that opening a public share link ran attacker JavaScript inside the viewer's authenticated chatgpt.com session, read private chats and took over the account. Early variants required a single click on the Preview button; a later variant executed on page open. Parameter reported October 18; OpenAI escalated from P2 to P1 on October 21 and shipped a server-side patch on October 26. Users did nothing. The bounty was $5,000; multiple commenters argued the payout was low relative to the severity. Parameter published its write-up October 28; coverage carried into October 31.

The Parameter team's write-up walks through the specific pieces of ChatGPT's share-link flow that line up into an account takeover. The vulnerability chains an escape from MathLive's rendering sandbox, which ChatGPT uses to display math in chats, into ChatGPT's share preview, which renders a shared conversation inside a logged-in viewer's own chatgpt.com session. The result is attacker JavaScript executing with the viewer's cookies and the ability to read private chats, exfiltrate conversations, or take over the account.

The patch timeline

Parameter reported the chain to OpenAI's security team on October 18. OpenAI initially triaged the issue as P2, then escalated to P1 three days later on October 21 after Parameter demonstrated the full account-takeover chain. The server-side patch shipped October 26. No user action was required; the fix was applied to ChatGPT's rendering pipeline. The bounty was $5,000. Several commenters, including Parameter itself in a later clarification, argued the payout was low relative to the severity of a one-click account takeover against a product used at ChatGPT's scale.

"The payload executed as chatgpt.com with access to the victim's authenticated web session." — Parameter, Do the Math: How We Took Over ChatGPT Accounts, 2026-10-28

Variant and exploitation

Parameter documented two variants of the exploit. The first required the victim to click the Preview button on the shared conversation once; the second triggered automatically on page open. Parameter did not report any evidence of the chain being used in the wild before disclosure; OpenAI's own post-patch review surfaced no abuse. The disclosure follows a pattern across the frontier labs this fall of pre-production chains being caught by bounty programs rather than internal red teams, and raises the question of what the labs' internal red teams are doing with their time if $5,000 bounties keep catching P1s.

Anthropic extends text watermarking to four Claude models; API users on two older ones can shut it off.

The Decoder · aiweekly.co · 2026-10-31 · Source ↗

The Decoder reported Anthropic will extend its invisible text watermark to Claude Mythos 5, Claude Opus 4.7, Claude Opus 4.6 and Claude Sonnet 4.6 to meet the EU AI Act's December provenance deadline. The watermark on Opus 4.7 and Mythos 5 holds across sampling settings; on Opus 4.6 and Sonnet 4.6 it only activates when three sampling parameters sit at their defaults. Developers who shift temperature, top-k or top-p off defaults can disable the signal on the older pair. Anthropic ties the loophole to the architecture of the older models and says it is still iterating. The watermark statistically biases Claude's word choices against a key Anthropic holds and signals "Claude was probably involved," not "who used it or why."

Anthropic has been shipping text watermarking since August and is now extending the signal to four more Claude models under the deadline the EU AI Act sets for provenance disclosure in December. The Decoder's report, picked up by aiweekly on Saturday, lays out which models get the watermark and where the signal is weaker. Claude Mythos 5 and Claude Opus 4.7 carry the watermark across their sampling configurations. Claude Opus 4.6 and Claude Sonnet 4.6, both pre-August launches that fall under the EU's transition period, carry the watermark only when the three main sampling parameters, temperature, top-k, and top-p, sit at their default values. Any developer who shifts a sampling parameter off default disables the watermark on the older pair.

Why the gap exists

Anthropic's explainer frames the gap as an architectural property of the two older models and says the team is still iterating on how to extend watermarking to them without retraining. The watermark works by biasing the model's word-choice distribution according to a pseudorandom key Anthropic holds, so Anthropic can later detect a watermarked passage with high confidence. On the newer models, the biasing is applied inside a layer the sampling parameters do not override; on the older ones, the layer sits downstream of sampling, so changing those parameters erases the signal. The company has committed to applying watermarking globally at launch for new models because it does not yet have a durable way to scope the signal by region.

"It indicates Claude was probably involved; it says nothing about who used it, or why." — Smithstephen commentary on Claude's watermark, cited by secondary coverage, 2026-10-31

What the watermark can and cannot prove

Several outlets reiterated that Anthropic's watermark is a statistical signal, not a proof. It can tell someone with Anthropic's key that a passage was probably generated by Claude, but it does not identify the user, the account, or the use case. The EU AI Act's provenance requirement is itself a signal-level ask rather than an attribution one, so Anthropic's implementation meets the letter. The loophole on Opus 4.6 and Sonnet 4.6 is the point where enforcement will meet its first real-world test: a developer who shifts top-p off default can defeat the watermark on two of the four models in the rollout. Anthropic says it will keep working on a sampling-independent watermark for the older architectures.

The walk-back

Sean Heelan flagged the change publicly, and the resulting backlash prompted OpenAI to send a second email promising personal Daybreak Blue users a separate way to opt out of model improvement for Daybreak sessions. Details, OpenAI said, would be published closer to November 29. Several outlets reported before the walk-back landed that no opt-out was being offered to personal users; after the second notification those claims became outdated inside a day. The resulting state is messy: the opt-out exists in principle, has not been implemented in product, and the terms of the implementation are not public as of Saturday.

"Starting November 29, OpenAI will use data from Daybreak Blue sessions to train its models, even when users have turned off training." — The Decoder summarizing the first OpenAI notification, 2026-10-31

What is still unchanged

Individual API access to Daybreak Blue ends November 20, which closes a secondary path researchers had used to avoid the Trusted Access flow. The second notification carves out an exception for interactions flagged for safety review, saying those may still be used for safety purposes regardless of opt-out status. The episode is unusual mostly for how fast the walk-back happened; across the frontier labs, published training-data policy has grown more rigid over the past six months, and OpenAI's willingness to concede an opt-out inside a day is the first visible evidence that the Daybreak-adjacent research community has influence over how its sessions are treated.
