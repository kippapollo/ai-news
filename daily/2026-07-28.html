MCP 2026-07-28 lands: stateless HTTP core, server-rendered Apps, twelve-month deprecation for Roots, Sampling and Logging

The Model Context Protocol's largest revision since launch finalizes Monday, ten weeks after the May 21 release candidate froze and four weeks after beta SDKs shipped in Python, TypeScript, Go and C#. The stateless core deletes the initialization handshake, moves protocol version and client info into per-request _meta fields, and lets a remote MCP server sit behind an ordinary round-robin load balancer for the first time. MCP Apps introduces server-rendered UIs in sandboxed iframes, Tasks graduates out of experimental as a stateless extension, six OAuth 2.0 and OpenID Connect hardening SEPs land in the core auth path, and Roots, Sampling and Logging enter a lifecycle policy that keeps them functional through at least May 2027 before earliest removal.

Model Context Protocol Blog · 2026-07-28 · Source ↗

The Model Context Protocol 2026-07-28 specification finalizes Monday as the largest revision since Anthropic released the protocol in November 2024. The release candidate was locked May 21 and has been publicly available for ten weeks of implementation feedback across Anthropic, OpenAI, Google, Microsoft and AWS. Beta SDKs shipped June 29 covering Python 2.0.0b1, TypeScript v2, Go 1.7.0-pre.1 and C# 2.0.0-preview.1. Today's finalization moves the protocol out of a period where every enterprise agent deployment carried an implicit expiration date attached to the RC and into a versioned lifecycle where features graduate, deprecate and retire on published windows.

"A remote MCP server that previously needed sticky sessions, a shared session store, and deep packet inspection at the gateway can now run behind a plain round-robin load balancer."— MCP Working Group, 2026-07-28 release notes

The stateless core

The initialize/initialized handshake and the Mcp-Session-Id header are gone. Protocol version and client info move into per-request _meta fields; a new server/discover method carries capability queries. That single change moves MCP from a session-oriented protocol closer in shape to a normal RESTful HTTP API. Operators can now route MCP traffic through ordinary Layer 4 load balancers without sticky-session configuration, without a shared session store between replicas, and without deep packet inspection at the gateway. The knock-on effects reach every enterprise MCP deployment: horizontal scaling stops requiring session affinity, replica failure stops producing user-visible reconnection errors, and the round-trip cost of the initialization handshake disappears from the tool-heavy interaction latency budget. Explicit handle patterns replace protocol-level state for applications that genuinely need stateful behavior: servers return identifiers, models thread them through subsequent tool calls, and state stays visible to the model rather than hidden in transport metadata.

MCP Apps and Tasks

MCP Apps introduces server-rendered HTML interfaces in sandboxed iframes with prefetchable templates and JSON-RPC bidirectional communication. A tool that previously had to serialize a chart as a base64-encoded image or leave rendering to the client can now return a live UI directly. That closes the 2024 spec's most-cited gap: graphical tool output. Tasks graduates from an experimental core feature to a first-class extension that operates statelessly with a client-driven lifecycle (tasks/get, tasks/update, tasks/cancel). An agent that kicks off a 15-minute analysis job no longer needs to hold an MCP session open the entire time; any server instance can pick up a task by handle. Multi Round-Trip Requests, another new addition, replace SSE streams for server-initiated interaction: an InputRequiredResult response can be handled by any server instance, so streaming state stops pinning traffic to a specific replica.

Operability upgrades

The Mcp-Method and Mcp-Name headers let gateways route without inspecting the JSON body. New ttlMs and cacheScope fields, modeled on HTTP Cache-Control, let clients cache tools/list responses for as long as the server permits. W3C Trace Context propagation standardizes distributed tracing across every SDK, which matters when a single agent request fans out across a dozen MCP servers behind an enterprise identity gateway and an operator needs to reconstruct the timing. Six SEPs harden OAuth 2.0 and OpenID Connect alignment: mandatory iss parameter validation per RFC 9207, application_type declaration during Dynamic Client Registration, issuer binding for registered credentials, and refresh token documentation for OpenID Connect servers. These are not new capabilities; they close specific attack surfaces that had been documented against MCP servers running the older auth path.

The deprecation lifecycle

Roots, Sampling and Logging enter the new lifecycle policy at Deprecated status with at least twelve months before earliest possible removal in a future revision, so all three remain functional through at least May 2027. Roots supplied filesystem exploration hints, better handled by explicit filesystem tools or resource URIs. Sampling let servers initiate model calls back through the client, better handled by direct LLM provider API integration when a server needs to make its own model calls. Logging offered structured server logs, better handled by stderr or OpenTelemetry. The working group's framing is not that these features fail; it is that the primitives fit an era when MCP servers ran on developer workstations, and the current deployment surface, which is enterprise infrastructure, favors different mechanisms. The published feature-lifecycle policy applies to every future revision: Active graduates to Deprecated with reason, Deprecated stays functional for at least twelve months, and then Removed lands in a versioned revision with an upgrade path documented.

What implementers face this week

Every SDK the working group maintains ships with a migration guide. TypeScript v2 splits the monolithic SDK into focused packages and provides a codemod to automate the rename from .tool() to registerTool. Python v2.0.0b1 replaces FastMCP with MCPServer while carrying the decorator API forward. Go and C# take a gentler path: Go keeps the module path, and C# retains v1.x compatibility with only spec-deprecated features marked obsolete. Enterprise MCP server operators have until roughly May 2027 to migrate off Roots, Sampling and Logging if they use them; the more pressing timeline for most teams is the handshake removal. Servers that assumed initialize/initialized would exist in every session need refactoring before any client updates to the 2026-07-28 spec, because the removed handshake is not backward-compatible with clients speaking the new revision. Microsoft's Agent Framework 1.12.1 shipped MCP Streamable HTTP hardening last week that maps directly to the new auth path. Anthropic's Claude Desktop, ChatGPT Desktop, GitHub Copilot's MCP surfaces, and every third-party MCP server on the awesome-mcp-servers list will land on the 2026-07-28 revision through Q3.

How the structure works

SoftBank's SB Energy would own and develop the campus as a public-private partnership with the US Department of Energy on the Portsmouth Gaseous Diffusion Plant site, a decommissioned Cold War-era uranium enrichment facility with existing high-capacity electrical interconnects. Aleksandar Tomic's public reading of the deal captures the concern Wall Street analysts voiced through Sunday: Nvidia guarantees the lease so OpenAI can sign for the building; the building runs on Nvidia chips OpenAI buys with Nvidia-adjacent financing; Nvidia books the chip revenue; OpenAI's ability to service the lease depends on future AI-services revenue that has to materialize at a scale sufficient to underwrite the entire structure. Tomic's other public line, "If everything is so hunky-dory in the AI ecosystem, why is this deal even needed?" reads as the specific investor question about whether debt markets would have priced OpenAI's Piketon lease at all without Nvidia's guarantee. None of the named parties have confirmed the arrangement on record; terms remain unsettled and the deal could collapse.

Ohio's data-center posture

Ohio hosts 166 operational data centers with 57 more in the planning pipeline, fourth-largest US state footprint by count. The Piketon site's specific attraction is its Cold War-era grid interconnect capacity and the DOE relationship inherited from the Portsmouth Gaseous Diffusion Plant. Piketon is 68 miles south of Columbus, giving the campus proximity to Ohio's existing hyperscaler concentration around New Albany without landing inside the transmission-congested zones utilities have flagged as unable to accept new interconnect requests before 2029. The Ohio decision is also a political one: Senator JD Vance's home state gets the anchor project of the Stargate infrastructure buildout OpenAI announced with Oracle and SoftBank in January 2025.

Nvidia open-sources NOOA: agents as single Python classes, 82.2 percent on SWE-Bench Verified

NVIDIA Technical Blog · 2026-07-27 · Source ↗

NVIDIA Labs Object-Oriented Agent (NOOA) landed on GitHub as an open-source agent-harness framework structuring each agent as a single Python class with capabilities, state and prompts integrated via methods, fields and docstrings. Type annotations serve as enforced contracts. On SWE-Bench Verified with GPT-5.5, NOOA reports 82.2 percent, above the prior 79.2 percent SOTA.

NVIDIA published the Labs Object-Oriented Agent (NOOA) framework Monday on GitHub as the open-source anchor contribution to the Open Secure AI Alliance launch. NOOA structures agents as ordinary Python classes: capabilities are methods, state is fields, prompts sit in docstrings, and type annotations become enforced contracts checked at construction time and again at tool-call time. The framework's stated goal is to make agent construction feel like ordinary object-oriented software rather than a prompt-engineering exercise wrapped in a framework-specific DSL.

What the numbers say

On SWE-Bench Verified with GPT-5.5 as the underlying model, NOOA reports 82.2 percent, above the previously published 79.2 percent SOTA harness on the same underlying model. Nvidia's claim of up to 50 percent operational-cost reduction against comparable harnesses covers total token spend across a workload, not per-request cost; the reduction traces to NOOA's structured state management, which avoids the "regurgitate the conversation history into every tool call" pattern that inflates token bills in less-structured harnesses. Independent benchmarking against Claude Sonnet 5 and Kimi K3 as underlying models has not landed as of Monday.

Why the design choice matters

Existing agent harnesses (LangChain's LangGraph, OpenAI's Agents SDK, Microsoft's Agent Framework, Anthropic's Claude Agent SDK) all layer state, tools and prompts through framework-specific abstractions. NOOA collapses those layers onto Python's native object model. That has an operational payoff for teams that already run large Python codebases and want agent logic to sit next to service logic without conceptual friction. The framework's engineering aesthetic also lines up with the object-oriented pattern the arXiv preprint at 2607.20709 describes, and the labs-OO-Agents GitHub repo now published sits inside NVIDIA-NeMo alongside the earlier labs-molt training framework.

The alliance context

NOOA is Nvidia's founding contribution to the Open Secure AI Alliance, which means the specific pitch is agent transparency for defenders: security teams that build agents on NOOA can inspect the agent class, reason about the state transitions, and audit the tool-call surface directly, without navigating framework indirection. That property matters for the alliance's core argument that defensive AI needs to be open and inspectable end-to-end.

NVIDIA's Molt tops Hugging Face Papers: PyTorch-native training for agentic RL

Hugging Face Papers · 2026-07-27 · Source ↗

Molt debuts on Hugging Face Papers Monday at 647 upvotes: a PyTorch-native training framework for agentic reinforcement learning that trains multimodal and MoE policies through a single asynchronous loop, never trains on tokens it did not generate, and reports statistical parity with a Megatron-based stack under matched conditions.

NVIDIA's Molt training framework debuted at the top of Hugging Face Papers Monday with 647 upvotes, published as arXiv preprint 2607.21653 alongside the open-source repository at github.com/NVIDIA-NeMo/labs-molt. Molt targets agentic reinforcement learning: training loops where the model produces multi-step trajectories interacting with an environment, and the policy updates use only tokens the current policy actually generated. The framework is written to keep the codebase compact enough for a researcher to hold in their head, and for an AI coding assistant to read and reason about end-to-end, so the algorithm flow can be traced and modified without navigating framework indirection.

The single-loop design

One asynchronous loop trains multimodal and mixture-of-experts policies while remaining consistent in tokens, policy versions and model semantics. The framework never trains on a token it did not generate; that constraint eliminates the off-policy contamination that has produced misleading benchmark results in several earlier agentic RL frameworks where a shared token buffer accumulated old-policy tokens the training step then used. Under a matched, fully asynchronous protocol, Molt reports statistical parity with a state-of-the-art Megatron-based stack, which means teams that had been paying Megatron's complexity budget for training throughput can now reach the same throughput on an ordinary PyTorch stack.

Why PyTorch-native matters here

Agentic RL is where the frontier is moving: OpenAI's o-series lineage, Anthropic's Sonnet 5 and Opus 5 training, Google's Gemini 3.6 Flash, all involve substantial RL training on multi-step tool-using trajectories. The training stacks for this work have historically been custom builds sitting on top of Megatron, DeepSpeed or JAX/Flax, and the fragmentation has made independent replication difficult. A PyTorch-native reference implementation with published recipes and containers, delivered by Nvidia and free of the Megatron dependency, moves agentic RL closer to being an ordinary training problem rather than a specialized one.

The paper cohort

Molt tops a Hugging Face Papers Monday queue that also carries DataPrep-Bench from Peking University (221 upvotes) on benchmarking LLMs as training-data preparators, Skill Self-Play from Qwen Business Unit-Edu (30 upvotes) on co-evolving skill systems, Agentic Context Management from Maximem AI (52 upvotes) on agent memory as a lifecycle problem, Interactive Training 2 from Waterloo (15 upvotes) on auditable control planes for live training, and Scaling Native Multimodal Pre-Training from Tencent Hunyuan (14 upvotes). The cohort's collective shape: infrastructure, evaluation, and training-methodology work rather than new model releases.

Skill Self-Play, from a Qwen Business Unit-Edu team at Alibaba, landed on Hugging Face Papers Monday at 30 upvotes as the third-ranked new submission. The training methodology extends AlphaZero-style self-play from games to open-ended skill acquisition: the model plays both sides of a skill-development interaction, generating tasks against itself, solving those tasks, evaluating outcomes, and updating both the task-generator and task-solver policies. The distinguishing move is co-evolution: skills evolve alongside the model, so the task distribution grows in difficulty as the model's capability grows, avoiding the classical failure mode where fixed benchmarks saturate and stop providing training signal.

Why co-evolution matters

Standard supervised fine-tuning saturates: once a model matches human-generated ground truth on the training set, additional training on the same distribution produces diminishing returns. Standard RLHF has the same shape once preference data is exhausted. AlphaZero's self-play innovation was that a game like Go supplies its own gradient because the opponent gets stronger as the model does. Skill Self-Play argues that open-ended skill acquisition can do the same thing if the skill space itself is parameterized and evolved alongside the model. The paper's headline result is a compounding gain on the specific skill-battery the Qwen team uses for evaluation, though independent replication has not yet appeared.

Where this fits

Skill Self-Play sits alongside Molt in the Monday Hugging Face Papers cohort as the second Chinese-frontier-lab paper on training methodology to trend the same day. Maximem AI reframes agent memory and cost as lifecycle and architecture problems

Hugging Face Papers · 2026-07-27 · Source ↗

Maximem AI's Agentic Context Management paper trending on Hugging Face Papers Monday at 52 upvotes argues that agent memory efficiency and operational cost are architectural design problems rather than model-tier prompt-engineering problems, and provides a lifecycle framework for context objects.

Maximem AI's Agentic Context Management paper published to Hugging Face Papers Monday at 52 upvotes. The paper's argument is a systems-engineering one: agent memory efficiency and operational cost are not properties of the underlying LLM, they are architectural properties of the harness surrounding it. Treating them as prompt-engineering problems (compressing conversation history, truncating oldest messages, summarizing threads) misses that the underlying issue is context-object lifecycle: when does a context enter working memory, when does it move to warm storage, when does it retire, and how do those transitions get scheduled without human intervention.

The lifecycle framework

The paper proposes a four-stage lifecycle for agent context objects: active (in the working prompt), archived (referenced by ID from working prompt, retrieved on demand), retired (available in cold storage, retrievable through a separate query), and expired (evicted per retention policy). Transitions between stages get scheduled through explicit policy rather than emergent behavior of an LLM prompt. That reframing lines up with the architectural work Anthropic and OpenAI have both discussed publicly around long-running agent deployments: cost scales with prompt length, and prompt length scales with unretired context, so lifecycle policy is the direct handle on operational cost.

Why the paper landed now

Enterprise agent deployments are hitting exactly the operational shape the paper describes. Claude Cowork, OpenAI Presence, Microsoft Cowork, and the specialized deployment surfaces at Salesforce, ServiceNow and SAP all run long-lived agent sessions that accumulate context. Teams operating these deployments are discovering that prompt-length management dominates cost. The paper's framework gives those teams vocabulary for a problem they had been solving ad hoc.
